input.h File Reference

Detailed Description

The Input::InputServer as a C boundary for the managed runtime.

The input server is event driven: events come in through the window and travel the handler chain, and the default keyboard and mouse handlers are the handlers that present what they received as a state an application can poll. This is that polling state, copied into a buffer C# owns.

The copy is only this frame's between the point where the events have been pumped and InputServer's EndFrame(), which is what clears the per-frame flags. In the game application the render feature unit pumps the window events at the start of its OnBeginFrame, and the script feature unit is attached after it, so the managed sync at the beginning of the managed frame is the point where the state is the frame's own.

What the state holds is what the input server received. ImGui gets the keys first and the window drops the events it consumes, so a key typed into a text field never reaches the handlers. That is what the focus and capture flags are for: they tell a caller that a key is missing because the UI took it rather than because nobody pressed it.
