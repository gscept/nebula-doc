Nebula.PropertyLevelFormat Class Reference

Detailed Description

The level format's contribution for managed properties.

The native side treats what this produces as text it does not interpret: it writes the text as a node under the entity, and it hands the text it read back here. That is what lets a property hold anything the json writer can express, and what lets a level written with this extension still be saved by a build that does not have it.

Entity references inside a property are written as the guid the file names the target by, and read back through the map the file gives. The level format cannot resolve them on its own, because it does not read this text, so it hands the map here before the call that needs it. Without a map a reference writes as null, which is what a build that has no file to resolve against gets.

One entity, put back from the json the file carried for it.

Exact: the entity's properties are the nodes the text names, and what it does not name is taken off. ◆ RecordChange()

void Nebula.PropertyLevelFormat.RecordChange ( ulong entityId,
Type type,
string fieldName,
string valueJson )
inlinestatic

The write path the inspector uses.

It does not write the field: it works out what the entity's text would be after the change and hands the before and the after text to the editor, which is what runs the change through a command. That is why the command is the only place a property changes, and why plugin code that sets a field directly does not record anything: a runtime change is not an authoring change.

A null field means the property is left out, which is what a removal reports. The path is what the recorder builds the override marker from, and it is the only thing that says which key inside the text changed. A property the entity did not have is reported as the whole property, which is what the recorder reads as an add: every key the after text carries for it is the entity's own.
