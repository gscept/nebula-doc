Game::LevelExtension Class Reference

#include <levelextension.h>

Detailed Description

A feature's contribution to the level formats.

The formats know an extension by name and treat what it produces as text they do not interpret, which is what lets a feature serialize something the engine has no type knowledge of.

The formats do not need the extension to write or read: they write the text capture produced as a node under the entity, and they hand the text they read back to apply. That is also what makes an extension the file carries but this build does not have survive a save, because the text is kept whether or not an extension can be found for it.

The hooks the merge needs are the ones that let the formats say something about text they cannot read: which keys the text carries, what the text looks like with only those keys, what one text gives when another text is put over it, and what one text gives for a named key when it does not carry it. They are used the way component reflection is used for a component's fields, and an extension without them is written whole, which is what a feature that has no authored fields gets.

Every hook that writes a text writes it in the same order: the nodes by name and the keys inside a node by name. The formats compare texts as bytes, because they cannot read them, and an order that differed between the hooks would read as a change that no value changed.

One text, one shape: the entity as one node per feature thing. The formats cannot read the text, so they cannot group it, and that is the only shape a file can carry. Everything that composes a text works in this shape, and an editor command holds this shape as well.

The formats also hand the extension the file's guid map, because the extension cannot resolve what its own text names. A text that names entities is written as the guids the file names them by, and the map is only valid for the duration of the one call that needs it.
